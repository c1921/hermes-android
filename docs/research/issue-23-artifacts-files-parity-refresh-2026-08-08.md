## Accurate and outdated report claims

- **Accurate:** Desktop has an Artifacts destination and a separate generated-artifact preview system; its global inventory is transcript-derived rather than a canonical server artifact catalog. The existing matrix’s statement that canonical generated-artifact delivery is absent remains accurate for the Desktop protocol.
- **Outdated as a status statement:** [`native-desktop-gap-refresh-2026-08-07.md`](native-desktop-gap-refresh-2026-08-07.md) and [`desktop-parity-refresh-2026-08-07.md`](desktop-parity-refresh-2026-08-07.md) predate the current #22 foundation and #23 dirty implementation, so their Android “missing artifacts/media” status is stale. Android now has a detected repository, adaptive screen, origin-route plumbing, bounded preview handling, and explicit SAF actions.
- **Misleading if read as completion:** Those new Android files do not establish 1:1 parity or satisfy all #23 acceptance criteria. In particular, profile-window completeness, originating-turn focus, process-death/provider cleanup, and the `/Users` parent-request regression still lack proof; the explicit parent row can still traverse outside the managed root.
- **Scope correction:** Android’s merged Artifacts/Files viewer is the native adaptation explicitly chosen by parent specification #11; it should not be described as a literal copy of Desktop's generated-artifact registry. Version history, right-rail semantics, and rendered/source controls belong in the later rich-renderer parity assessment.

The 2026-08-07 parity status is therefore **materially stale about Android’s implementation status**: it predates the #22 repository foundation and current #23 viewer work. It is **not stale** on the narrower protocol claim that Desktop has no canonical generated-artifact descriptor/delivery contract. Remaining #23 gaps are client-owned: profile-aware pagination, parent-boundary navigation, origin-turn focus, process-death/provider cleanup, runtime/request-trace coverage, and any deliberate separation of global versus generated artifacts. There is no server blocker for the current transcript-derived flow; strict reproduction of a canonical generated-artifact inventory would require a new Desktop/backend contract and is outside the current client-only work.

## Issue #23 completion contract

Keep #23 open until the following evidence is present:

1. Query the selected backend/profile with pagination or server-side profile filtering; verify an artifact opens the correct conversation and focuses the originating message/turn.
2. Verify phone full-screen and expanded list/detail behavior on the configured Android target(s), including selected-item restoration.
3. Verify HTML/SVG isolation with a network/request-trace assertion; verify explicit read-only SAF actions and cleanup of provider grants/shared files across process death.
4. Verify Conversation → Files → preview/directory back consumes local state before route pop and never requests a parent above the managed root.
5. Add a real/fake backend regression that records requests from `/Users` and asserts no `/` request and no `.VolumeIcon.icns` response/error is surfaced.
6. Add process-death, provider cleanup, origin-focus, phone/expanded, and route/back tests; rerun the repository’s applicable lint, unit, instrumentation, and build gates.
