## Current-main deltas — not shipped Desktop requirements

After the v0.20.0 tag, current `main` adds two Desktop reliability changes:

1. [`33edfe9`](https://github.com/NousResearch/hermes-agent/commit/33edfe9a8) (2026-08-07) recovers session-scoped RPC actions after a stale runtime-session drop, including tile actions, attachments, rewind, and slash/prompt operations.
2. [`10a2b3d`](https://github.com/NousResearch/hermes-agent/commit/10a2b3d7a) (2026-08-07) makes Files-pane workspace cwd ownership follow the selected session atomically; its companion gateway change reports a lazy session's own cwd.

These commits are in the pinned `main` baseline but post-date the shipped tag. Android should preserve the same durable-session/runtime-session and session-owned-cwd semantics through [`SessionRestoration.kt`](../../app/src/main/java/com/nousresearch/hermes/data/SessionRestoration.kt) and [`HermesRepository.kt`](../../app/src/main/java/com/nousresearch/hermes/data/HermesRepository.kt#L430-L510), but they should not be described as features already delivered by the shipped Desktop package.

## Recommended parity order

1. Add and advertise an explicit remote-profile webhook contract upstream, then complete Android CRUD: list, explicit enable/restart receipt, bounded create payload, toggle, confirmed delete, exact acknowledgement validation, and transient one-time secret.
2. Decide whether Android’s voice target is one-shot native playback or the shipped Desktop conversational contract; if 1:1 parity is required, add the stream/barge/wake contract as a separate feature.
3. Reconcile current-main stale-session recovery and session-owned cwd behavior, then add release/device proof for Android-specific adaptations.
4. Keep Desktop plugin SDK, quick entry, and multi-window behavior documented as native-platform adaptations unless an Android equivalent is explicitly required.
